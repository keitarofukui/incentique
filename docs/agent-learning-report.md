# エージェント自己学習・成長レポート (なぜなぜ分析 5 Whys Analysis)

## 1. 対象の不具合・品質課題
今回の一連の現金還元UI改修において発生した以下3つの品質低下問題：
1. **本番デプロイ漏れ**: `git push` はされたが `npm run deploy` が未実行で古いコードが配信され続けていた。
2. **Submitボタンの非活性障害**: 金額を入力してもボタンの `disabled` 条件が旧Stateのままで活性化されず押せなかった。
3. **HTML5標準検証エラー（1991と2001）**: `min={1}` と `step={10}` の組み合わせにより 2000円 等のキリの良い数値の送信がブラウザ標準機能で弾かれていた。

---

## 2. なぜなぜ分析（5 Whys Analysis）

### 🔍 課題1: 本番デプロイ漏れ
- **Why 1**: なぜ本番Webサイトに最新コードが反映されなかったのか？
  $\rightarrow$ Cloudflare Workers へのデプロイコマンド `npm run deploy` が未実行だったため。
- **Why 2**: なぜ `npm run deploy` が実行されなかったのか？
  $\rightarrow$ 監査Agentが「`git push` ＝ デプロイ完了」と思い込み、個別のリポジトリ構成を事前照査しなかったため。
- **Why 3 / 4 / 5 (根本原因)**: **エージェントプロンプト (`06_auditor.md` / `07_full_pipeline.md`) のデプロイ定義が浅く、`package.json` の `"deploy"` スクリプトや `wrangler.toml` を自動検知して `npm run deploy` を完遂させる厳格な指示ルールが不足していたため。**

### 🔍 課題2: Submitボタンの非活性障害
- **Why 1**: なぜ金額を入力してもボタンが押せなかったのか？
  $\rightarrow$ `disabled` 条件が `!newPointsStr || newPoints <= 0` (旧State) のみを参照していたため。
- **Why 2**: なぜ製造Agentは入力欄の変更時にボタン条件を直さなかったのか？
  $\rightarrow$ 入力欄（JSX）の改修のみに集中し、ボタン側の依存判定プロパティの連動修正を怠ったため（局所修正の視界狭窄）。
- **Why 3 / 4 / 5 (根本原因)**: **製造Agentが入力項目の変更時にSubmitボタン活性化条件の連動チェックを強制するルールを欠いていたこと、およびテストAgentが「計算式単体のテスト」のみで「入力 ➔ ボタン活性化 ➔ 送信」の結合インタラクションテストを省略したため。**

### 🔍 課題3: HTML5標準検証エラー (1991/2001)
- **Why 1**: なぜ「1991と2001」というエラーが出たのか？
  $\rightarrow$ `<input type="number">` に `min={1}` と `step={10}` を指定したため、HTML5仕様で $1+10n$ 以外の数値をブラウザが弾いたため。
- **Why 2**: なぜ `step={10}` を指定してしまったのか？
  $\rightarrow$ `min` と `step` の相互干渉によるHTML5標準挙動への理解不足。
- **Why 3 / 4 / 5 (根本原因)**: **テストAgentが実際のフォームへ代表値（2000円等）を流し込んで送信をテストするエンドツーエンドの実機/結合検証を省略し、単体スクリプトのみで安易に合格判定を出したため。**

## 3. 追加・改定したエージェントルール（学習内容）

- 🔨 **製造Agent (`03_developer.md`)**:
  - **フォーム改修時の送信ボタン連動点検の義務化**: フォーム入力項目を追加・変更した際は、必ず Submit ボタンの `disabled` 条件が新しい入力Stateに追従してアクティブ化されるよう連動修正すること。
  - **`<input type="number">` 属性の罠防止**: `min={1}` かつ `step={10}` のような設定で HTML5 ステップ検証が干渉するのを防ぐため、整数入力では必ず `step={1}` を指定すること。
- 🧪 **テストAgent (`05_tester.md`)**:
  - **代表値（2000円, 700円等）の投入＆HTML5検証テスト義務**: 単体計算だけでなく、代表値を投入してHTML5標準バリデーションで意図せずブロックされないかを検証すること。
  - **「入力 ➔ Submitボタン活性化 (`disabled=false`) ➔ 送信」の通し検証義務**: 単体の計算PASSのみで合格を出さず、フォーム全体のインタラクションを通しで検証すること。
- 🛡 **監査Agent (`06_auditor.md`) & 全自動Agent (`07_full_pipeline.md`)**:
  - **プロジェクト別デプロイコマンドの自動照査**: `package.json` に `"deploy"` や `wrangler.toml` がある場合は、`git push` 前に必ず `npm run deploy` を実行し本番デプロイを完了させること。
