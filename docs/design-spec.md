## 3. バックエンド計算ロジック改修仕様 (`src/backend/index.ts`)

### ① 「本日素点達成」判定のガードレール強化
ストリーク日数のインクリメントおよびボーナス判定において、**本日の累計素点 (`todayPoints`) が規定閾値に到達していること**を必須条件とする。

- **通常ストリーク**: アクション実行（`user.last_action_date !== logicalToday`）で判定。
- **中級ストリーク**: `todayPoints >= midThreshold` (100pt) を本日初めて満たした時に `current_50pt_streak_days` を更新・判定。
- **神ストリーク**: `todayPoints >= godThreshold` (300pt) を本日初めて満たした時に `current_100pt_streak_days` を更新・判定。

★ **本日の素点が閾値未達のストリークラインは、過去の日数がDBに存在しても本日のボーナス算出計算に一切含めない。**

### ② 上書きバグ (`Math.max`) の撤廃と加算・独立評価ロジック
現行の `if (b > targetMaxStreakBonus) targetMaxStreakBonus = b;` による上位判定での上書きを廃止する。

- 達成条件を満たした各ストリークライン（通常・中級・神）の目標ボーナスを個別に算出する。
  - 例: 通常7日連続 (70pt)、中級7日連続 (210pt)
- 定義仕様に基づき、達成したラインの最大達成ボーナス額、または合算ボーナス額を正しく評価してステップアップ差額給付（`stepUpBonus`）を計算する。

### ③ 日を跨いだ既給付マイルストーンの重複受給防止
- `action_logs` 内の過去のボーナス給付履歴クエリを改善し、同一マイルストーン日数（例: 4日目）に対するボーナスが日を跨いで繰り返し付与されることを完全に遮断する。

