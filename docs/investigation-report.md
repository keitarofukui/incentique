# 調査報告レポート: ブラウザ標準フォーム検証エラー（「1991と2001」吹き出し）の原因調査

## 1. 調査目的 & 概要
ユーザーより、換金希望金額に `2000` 円を入力して送信した際に、ブラウザから**「有効な値を入力してください。有効な値として最も近いのは 1991 と 2001 です。」**という不可解なエラーダイアログが表示され、フォームが送信できない問題の原因調査。

---

## 2. 結論（事実・ファクト）

### 結論: **`<input type="number">` の `min={1}` と `step={10}` の組み合わせによる HTML5 標準ステップ検証の干渉が原因です。**

---

## 3. なぜ「1991 と 2001」というエラーが出るのか？（メカニズム）

1. **HTML5 の `<input type="number">` ステップ算出仕様**:
   HTML標準の数値入力フォームでは、許可される入力値は以下の計算式で決定されます：
   $$\text{有効な入力値} = \text{min} + (\text{step} \times n) \quad (n \ge 0 \text{ の整数})$$

2. **実際のコードにおける設定値 (`WishlistSection.tsx` L567-L568)**:
   - `min = 1`
   - `step = 10`

3. **許可される値の列挙**:
   - $n=0 \rightarrow 1 + 0 = 1$
   - $n=1 \rightarrow 1 + 10 = 11$
   - $n=2 \rightarrow 1 + 20 = 21$
   - ...
   - $n=199 \rightarrow 1 + 1990 = 1991$
   - $n=200 \rightarrow 1 + 2000 = 2001$

4. **結果**:
   下1桁が `1` の金額（`1991円`, `2001円` 等）しかブラウザ標準の検証を通過できず、`2000円` や `700円` などのキリの良い金額を入力して Submit ボタンを押した際、ブラウザ自身が「`2000` は `1 + 10n` の倍数に合致しない」として送信を強制ブロックし、エラー吹き出しを表示していました。

---

## 4. 解決策
- `step={1}`（または `step="any"`）に変更。
- これにより、`1円` 以上のすべての整数金額（`2000円`, `700円`, `500円` 等）が何の問題もなくブラウザ標準検証を通過し、送信可能となります。
