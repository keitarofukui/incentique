# 調査報告レポート: 現金還元（お小遣い換金）入力UIの「円指定・ポイント逆算」化に関する実現性調査

## 1. 調査目的 & 概要
現在、ご褒美交換（`WishlistSection.tsx`）で「現金還元（7掛け/70%還元）」を申請する際、ユーザーは「交換ポイント数 (pt)」を入力し、システムが受取金額「〇〇円」を表示する計算方式となっています。
ユーザーより**「N円分換金したいという入力が自然であり、ポイントから計算するのは面倒。換金希望額（円）を入力したら必要ポイント（pt）が逆算表示されるUIにできるか？」**という要望を受けたため、現状のコード構造、計算ロジック、データベース/APIとの互換性、および具体的なUI設計案について調査・分析を行いました。

---

## 2. 現状のコード構造・ファクト（事実）

### ① フロントエンド入力UI (`WishlistSection.tsx`)
- **現行挙動**:
  - `itemType === 'cash'` 選択時も、入力フィールドの主軸は「交換ポイント (pt)」 (`newPointsStr`) となっている。
  - 受取金額は `Math.floor(newPoints * 0.7)` 円としてリアルタイムプレビュー表示される。
  - タイトルは自動的に `現金還元 (〇〇円)` と設定されて送信される。

### ② バックエンド API & DB データ構造 (`src/backend/index.ts` / D1 `wish_items` テーブル)
- **DB保存データ**:
  - `title`: 商品・還元名 (例: `現金還元 (700円)`)
  - `required_points`: 交換に必要なポイント数 (INTEGER)
  - `item_type`: `'goods'` または `'cash'`
- **API挙動**:
  - `/api/wish-items` (POST) では `requiredPoints` (pt) をそのまま受け取りDBに格納。
  - つまり、**バックエンド/DB側は「必要ポイント数」を数値として管理しているのみ**であり、フロントエンドで「希望金額（円）」から「必要ポイント（pt）」を逆算して送信すれば、バックエンドやDBの構造変更・マイグレーションは**一切不要**。

---

## 3. 分析・技術的実現性 & UI設計案

### 結論: **完全実現可能**
フロントエンド（`WishlistSection.tsx`）のモダールコンポーネント内の状態管理と計算ロジックを微修正するだけで、既存のデータベースやAPIに影響を与えずに安全に実装可能です。

---

### 具体的なUI・逆算ロジック設計案

#### 1. 入力モードの切り替え
- **物品 (`itemType === 'goods'`)**: 
  - 従来どおり **「交換ポイント (pt)」** を入力（タイトル、商品URL等も入力可能）。
- **現金還元 (`itemType === 'cash'`)**: 
  - 主入力欄を **「換金希望金額 (円)」** (`cashAmountStr`) に変更。

#### 2. 必要ポイントの逆算ロジック（7掛け還元）
現金還元率は 70%（0.7）のため、希望金額 $C$ 円に対する必要ポイント $P$ は以下のように算出します：

$$\text{必要ポイント } P = \left\lceil \frac{\text{換金希望金額 } C}{0.7} \right\rceil = \left\lceil C \times \frac{10}{7} \right\rceil$$

*(端数は切り上げてポイントを設定することで、指定した希望金額を確実に受け取れるようにします)*

**計算例**:
- **700円** 換金したい場合:
  - $700 / 0.7 = 1,000$ pt
- **500円** 換金したい場合:
  - $\lceil 500 / 0.7 \rceil = \lceil 714.28... \rceil = \mathbf{715\text{ pt}}$
  - (※ 715 pt × 0.7 = 500.5 円 ≒ 500円還元)
- **1,000円** 換金したい場合:
  - $\lceil 1000 / 0.7 \rceil = \lceil 1428.57... \rceil = \mathbf{1,429\text{ pt}}$

#### 3. 「全額換金」ボタンの挙動
- 所持ポイントを $P_{user}$ pt とした時、換金可能な最大現金金額は：
  $$\text{最大換金可能額 } C_{max} = \lfloor P_{user} \times 0.7 \rfloor \text{ 円}$$
- 「全額換金」ボタンが押された場合、換金希望金額入力欄に $C_{max}$ を自動セットします。

#### 4. リアルタイムプレビュー＆メッセージ表示
- 換金希望金額（例: `700` 円）が入力されると、下部に以下をリアルタイム表示：
  - **💵 必要なポイント**: `1,000 pt`
  - **所持ポイント**: `1,250 pt` (残り `250 pt`)
  - ※必要ポイントが所持ポイントを超過している場合は、赤字警告を表示し登録ボタンを無効化。
