# 調査報告レポート: クイズを50問以上やるとポイントが加算されない不具合の原因調査

## 1. 調査目的 & 概要
次男（ユーザー: シュンタロウ様）より「クイズを50問以上やるとポイントが加算されない」との不具合報告を受領。
DBの過去データおよびフロントエンド・バックエンドの処理ロジックを詳細に調査し、原因を特定しました。

---

## 2. 調査結果（結論）

### 結論: **DB（バックエンド）ではポイントは正常に加算・保存されていますが、フロントエンドの「APIログ取得件数上限（50件制限）」および「クイズバッチ（48問）切り替え時の非同期バグ」により、画面上で50問を超えた際に過去のログが押し出されて集計表示がストップ・減少して見える状態が発生していました。**

---

## 3. 過去データ詳細調査結果（DBエビデンス）

Cloudflare D1 データベースの本番データを詳細照合した結果は以下の通りです：

### シュンタロウ様 (`user_1784723445812_y29a`) の日別クイズ実行履歴
- **2026-08-14**: 60問解答 / 130pt 獲得
- **2026-08-13**: 154問解答 / 278pt 獲得
- **2026-08-10**: 83問解答 / 164pt 獲得
- **2026-07-23〜07-30**: 計51問解答 / 86pt 獲得

### ポイント整合性チェック
- **`action_logs` テーブル全獲得ポイント合計**: **5,064 pt**
- **`users` テーブル `current_points` 保有ポイント**: **5,064 pt**

👉 **検証結果**: バックエンドDB層においては、50問を超えて100問〜150問以上解いた場合でも、**毎正解ごとに `current_points` および `action_logs` は100%正確に加算・保存**されており、過去データを含めてポイントの未加算やデータ損失は発生していません。

## 4. 画面上で「ポイントが加算されない」と感じた根本原因（メカニズム）

画面表示において「50問以上やるとポイントが入らない・増えない」とユーザーが体験した原因は、以下の **2つの実装上の不具合** です。

### 原因①: `GET /api/action-logs` の デフォルト `LIMIT 50` 件数上限（メイン原因）
1. **問題箇所**: [`src/backend/index.ts`](file:///Users/fukuikeitaro/Documents/game/src/backend/index.ts#L1000) および [`src/frontend/App.tsx`](file:///Users/fukuikeitaro/Documents/game/src/frontend/App.tsx#L133)
2. **発生メカニズム**:
   - バックエンドの `GET /api/action-logs` エンドポイントは、`limit` パラメータが指定されない場合 **デフォルトで `LIMIT 50`** （最新50件のみ）を返します。
   - `App.tsx` ではパラメータ無しで `fetch('/api/action-logs')` を呼んで全ログを状態 (`actionLogs`) に保持しています。
   - ユーザーが1日にクイズを 50問以上解くと、最新50件のログ枠がそのクイズログで埋め尽くされます。
   - すると、**50件より前に実行されたアクション（過去のクイズや読書・運動・食事などのログ）が最新50件の枠から押し出され、画面上の `actionLogs` から消滅**します。
   - フロントエンドのダッシュボード（クイズ累積正解数）、カテゴリグラフ（`DailyChart`）、本日達成ステータス（`PersonalStreakCard`）などは、この `actionLogs` を元に計算しているため、50件を超えた時点で表示上の集計ポイントが頭打ちになったり減ったりし、「ポイントが増えなくなった」ように見えます。

---

### 原因②: `QuizQuest.tsx` の 1バッチ48問到達時の非同期再取得バグ
1. **問題箇所**: [`src/frontend/components/QuizQuest.tsx`](file:///Users/fukuikeitaro/Documents/game/src/frontend/components/QuizQuest.tsx#L135-L146)
2. **発生メカニズム**:
   - バックエンドの `GET /api/quizzes` は、1回の呼び出しで **最大48問** (学科45問 + アニメ3問) を取得します。
   - 48問を解き終わって「次の問題へ（`handleNext`）」を押した際、`fetchQuizzes()` が非同期(async)で実行されますが、`await` されておらずローディング状態の制御もありません。
   - そのため、48問目直後に「次の問題へ」を押すと、**画面上に48問目と同じ問題が未回答状態で再表示**され、49問目〜50問目付近で選択肢を押しても同じ問題への重複送信が発生したり、非同期取得完了時のインデックス切り替えラグで画面のポイント更新が止まったように感じられます。

---

## 5. 推奨される修正方針

1. **`GET /api/action-logs` の取得上限・クエリ最適化**:
   - `App.tsx` または各コンポーネントで `user_id` や日付範囲（例: 当月分など）を指定して取得するか、十分な件数（例: `limit=500` 等）を取得するよう変更。
   - 親ポータル・ダッシュボード等の集計で、最新50件制限の影響を受けない構造に修正。

2. **`QuizQuest.tsx` の非同期バッチ取得の改修**:
   - 48問終了時の `fetchQuizzes()` 呼び出し中にローディング状態を表示し、重複解答や画面のフリーズ・遅延を防止。
